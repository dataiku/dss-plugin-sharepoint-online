- Use this dataset to read rows from a SharePoint Online list or write to a list as the output of a DSS recipe. Select it for list items rather than document files.
- For `auth_type="oauth"`, select an accessible `sharepoint_oauth` preset from `oauth-login`. For `auth_type="app-certificate"`, select `app_certificate` from `app-certificate`. For `auth_type="app-username-password"`, select `app_username_password` from `app-username-password`. Set the authentication method explicitly; the descriptor has no default.
- Presets supply the tenant and default site path. Select presets by reference. When the tenant or site matters to the request, rely on values explicitly stated in the preset description or confirmed by the user.
- The authenticated user or application needs read access for reading and write access for writing. If authentication setup is incomplete, ask the user to finish it in DSS settings; do not request passwords, tokens, certificates, or private keys in chat.
- Set `sharepoint_list_title` to the exact list title, not its URL or ID. Ask for the intended list when it is unknown; the `DSS_${projectKey}_` default is not evidence of an existing list. List titles used for writing cannot contain `?`.
- Leave `sharepoint_site_overwrite` unset to use the preset's site. A supplied site name alone does not require an override; ask if the preset's target site is unclear.
- Override only for an explicitly requested site change. Set `advanced_parameters=true` and copy the confirmed URL's site path: `https://tenant.sharepoint.com/sites/TeamSite` becomes `sites/TeamSite`. Preserve `sites/`, `teams/`, and subsites; ask for the full URL instead of guessing. The preset's tenant remains unchanged.
- To read a named view, set `advanced_parameters=true` and `sharepoint_list_view_title` to its exact name. Leave the title empty to use the default view. Check the detected schema before referencing columns. DSS uses SharePoint field display titles as column names.
- The connector automatically fetches additional pages of list rows.
- Lookup and Person fields return JSON with IDs, display values, and optional attributes (e.g. email address, department or job title for Person fields). There is no equivalent to native "Display value" mode. `expand_lookup` is unused; do not set it.
- Exclude SharePoint-managed or read-only fields, such as `ID`, `Created`, `Modified`, `Created By` and `Modified By`, from the output data.
- Configure append or overwrite on the producing DSS recipe, such as the Sync recipe's "Append instead of overwrite" option. Append requires an existing list and adds new items; it does not update matching items. It can also create missing columns from the input schema. Retrying an append can duplicate items.
- Overwrite recycles the existing list and creates a new list with columns derived from the input schema. For a new list, use overwrite to create it. For an existing list, clarify ambiguous write intent before choosing overwrite; it replaces the list rather than only clearing rows.
- With `advanced_parameters=true`, `max_workers` controls write concurrency (1–5, default 1) and `batch_size` controls items per batch (1–100, default 100). Multiple workers can change item order.
- For new lists, enable `advanced_parameters=true` and `allow_string_recasting=true` when writing string columns. For existing lists, preserve column types. Only enable recasting after confirming that conversion to multiple-line text is acceptable. Single-line text values can be truncated to 255 characters if conversion is disabled or fails.
- Saving configuration does not write SharePoint items. Previewing and schema detection access SharePoint; executing a producing recipe writes to the remote list. Run or retry writes only when the user's request authorizes that operation.
- After writing, double-check the expected rows and values by reading the destination list back before reporting success, even if the job status and "items written" logs indicate success.
